Грид-торговля по шагам

Paper-only reference: исторический scanner snapshot и единый контекстный risk policy. Текущие цены/ликвидность не подключены; запуск ордеров запрещён.

1 · Что такое грид

Грид-бот ставит лесенку лимитных ордеров в диапазоне: покупает ниже текущей цены, продаёт выше. Каждое колебание внутри диапазона — пойманная разница. Грид зарабатывает на боковике и волатильности, не на тренде. Главный риск — выход из диапазона. Канон ниже различает unleveraged spot inventory и leveraged/derivatives; универсального правила «один стоп для всех» нет.

2 · Откуда берём монеты (наш эдж)

Не с потолка — из арена-сканера лоу-капов (LIVE_DEGRADEDscanner endpoint): ~112 монет в snapshot 2026-07-02; current scanner OFFLINE. Исторические поля: капа, объём 24ч, спред (bps), глубина стакана ±2%, DRS (риск делиста) и firewall. Для грида берём тайтовый спред + зелёный firewall + низкий DRS. Дашборд грид-лаба: LIVE_DEGRADEDarena-grid-lab.

3 · Сетап за секунду

python grid_setup.py SYMBOL [СУММА_USD] [ЧИСЛО_СЕТОК] [ПЛЕЧО]
# пример:
python grid_setup.py VANRYUSDT 150 24 1

Не включённый в этот candidate tool по историческому описанию должен был читать цену/волатильность и отдавать блок «GRID-BOT» (низ/верх диапазона, сетки, сумма, стоп) + таблицу ордеров + JSON.

4 · Куда вставлять

Любая биржа с грид-ботом в UI (Bitunix и т.п.) — четыре поля: Lower price, Upper price, Grids, Investment+Leverage. Risk control выбирается по контекстному канону ниже; этот paper guide не создаёт ордер. Лоу-капы — Binance; мид-капы (ARB, SUI, INJ) — Hyperliquid/Bitunix.

5 · Канонический contextual risk policy

Общий gate: эта поверхность PAPER_ONLY; can_trade=false; capital_permission=DENY. План не является разрешением на ордер.

  • Unleveraged spot inventory: заранее фиксируются loss budget, нижняя граница диапазона и manual/kill-switch exit. Механический stop внутри normal grid range не обязателен, но выход по бюджету/границе обязателен.
  • Leveraged, margin, futures или short inventory: hard stop и max-loss должны быть заданы до входа. Без атомарно enforceable stop исполнение OFFLINE.
  • Любой контекст: отсутствие подтверждённых свежих price/liquidity/DRS данных блокирует setup. Никаких API keys, orders или auto-execution в R51.
