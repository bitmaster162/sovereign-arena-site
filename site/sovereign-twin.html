The bug R21H closed

Почему H вообще понадобилась

До R21H

Runtime мог считать FAST готовым, затем выполнить embedding readiness, после чего LM Studio менял residency. Первый реальный запрос попадал в stale assumption и мог получить unloaded-model failure.

R21H

Embedding readiness выполняется до финального FAST acquisition. После этого runtime повторно проверяет residency, получает FAST через streaming-JIT путь и только затем bind-ит HTTP server.

01Embedding readinessПроверить embedding path первым.
02Residency re-probeНе доверять старому состоянию FAST.
03FAST acquireStreaming/JIT acquisition вместо отдельного explicit load.
04Exact evidenceПодтвердить ровно один FAST instance.
05HTTP bindСервер становится доступным только после readiness.
06Stable readyFAST resident, DEEP cold, memory unchanged.
Why stop here

Почему не R21I прямо сейчас

Current invariants

Что R21H гарантирует в текущей baseline

Canonical memory

Переход runtime не изменил каноническую memory DB; старый legacy DB сохранён.

Cold DEEP

Тяжёлая DEEP модель не обязана висеть в памяти постоянно; normal ready state держит FAST.

Explicit authority boundary

Runtime может анализировать и отвечать, но execution/capital/trading authority не выдаётся автоматически.

Source = runtime

После cutover активный source SHA совпадает с protected merged master.

Autostart

Windows Scheduled Task запускает актуальный R21H launcher после входа/старта окружения.

Rollback preserved

Предыдущий venv и metadata backup оставлены для controlled rollback.
